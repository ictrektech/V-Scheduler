# V-Scheduler 资源调度

打开「API 文档 → 应用接入 → 为接入应用指定执行节点」，在内置文档中查看目标节点部署、权重校验、模型登记以及指定节点执行的流程与请求示例。Scheduler API 契约保持一致。

展开 VOS 应用组的「V-Scheduler」，可直接进入模型与调用、模型与上游、推理部署、试聊、权重管理、镜像仓库、资源与任务、管理页面及 API 文档。点击「API Key」生成个人 Key 后，在结果区复制局域网 Base URL 和 Key，模型从该 Key 可见的列表选择。无共享挂载时的权重准备规范可在「API 文档 → 跨节点模型权重传输」下载。

Image Studio 同一模型的主节点和每个可调用计算节点分别占一行。「测试」和「调用方式」固定到该行节点。主节点使用本机调用，远端请求携带 `compute_deployment_id`。VOS 管理员可在「模型设置」直接放行或取消放行，对应 `PUT /api/v1/model-routing`。

「推理部署」页面会自动恢复 VOS 会话。恢复期间保留已加载的数据，页面统一显示恢复进度，恢复后刷新当前视图。

要让 VOS 应用在其他节点运行，直接在应用里选择匹配的已登记计算节点，部署后端并准备模型。目标后端优先使用只读的 Model Hub NFS。共享不可用时，可从已记录的字节偏移续传权重。权重通过 SHA-256 校验、目标节点符合模型实测校准后，调度器登记执行器。部署、传输和执行端点见调度 API 参考。

在「模型与上游」添加或编辑模型时，通过「思考控制」填写上游支持的 Chat Completions 格式和档位。兼容客户端可从模型目录的可选字段 `reasoning_control` 读取。

## 镜像仓库

VOS 管理员打开 **V-Scheduler → 镜像仓库**。用「拉取镜像」把上游镜像存入本地仓库，已有镜像可按仓库或标签同步。离线环境可用「导入镜像」上传 Docker 或 OCI 归档，省略目标名称时保留归档中的镜像名。任务面板显示进度和失败原因。仓库的管理数据与镜像层分别保存在应用的 `image-hub/` 和 `image-registry/` 持久化目录。

部署时，在镜像详情复制标签的部署地址。到 **高级管理 → 节点管理 → 应用后端**，选择应用和节点，部署使用应用清单中的匹配镜像。默认数据端口为本机 `127.0.0.1:36113`。跨节点部署时，在 VOS 应用配置里将 `SCHEDULER_IMAGE_HUB_BIND` 改为该节点可达的宿主机内网地址，并按目标 Docker 的要求配置对此 HTTP 仓库的访问。数据端口供受信网络使用。

删除标签或仓库后，可在「垃圾回收」中先预演，再释放无引用的镜像层。操作范围为 V-Scheduler 的仓库数据。使用中的部署应保留相应标签，方便之后重新拉取。在侧栏打开「API 文档 → 镜像仓库 API」查看管理接口。请求使用 VOS 管理员 Bearer token。

VOS 管理员在「权重管理 → 模型接入状态」可查看权重进度、服务状态和执行位置。内置 Ollama 显示本机 VOS，外部服务显示网关连接的上游主机。若上游使用代理，其后的物理节点无法确认。远程权重标为由上游管理。在「模型与上游」选择模型并点「测试」，发送试聊请求后返回状态页查看实际选中的上游、结果和时间。失败可在试聊中查看可达性、网络、鉴权、模型未加载或超时等原因。同一登录身份在当前浏览器刷新后仍能看到每个模型与上游的最近结果。浏览器清除站点数据或禁用本地存储时，刷新后可能无法恢复。

GET /api/v1/model-lifecycle 需要 VOS 管理员。download 为 null 或包含 phase 和 0–1 的 progress；model_running 为布尔值或 null；upstream_models 中 weight_source 为 upstream 或 unlinked。POST /api/v1/upstreams/probe 返回可选的 diagnosis 和 test_diagnosis，包含 code 和 reachability（reachable、unreachable、unknown）。试聊通过正常 /v1 接口调用。 界面使用既有 GET /api/v1/upstreams 的 id、source 和 base_url，仅从地址显示主机与端口；使用 GET /api/v1/auth/me 的 auth_method 和 identity.sub 隔离当前浏览器中的试聊结果。最多保留 200 个模型与上游的最近状态、时间和主机，试聊内容不写入存储。API 契约无变化。

新增「推理等待队列」及「模型仓库 → 模型接入状态」。试聊默认有界等待 120 秒，支持查看位置和取消；应用可通过网关排队请求头选择交互或后台优先级。自带 Ollama 默认空闲保留 60 秒，同模型连续调用可复用；保留期间继续占完整资源预约，切换、到期或手动停止后先确认卸载再释放。管理员可设置 0..600 秒，0 为每次卸载。服务注册支持 metadata.model_bindings 精确关联仓库权重与后端模型名称，状态页统一显示路由、后端健康和调度绑定。现有模型目录、九组端口、host alias 和四个容器保持兼容。

统一包包含模型网关与调度控制器。模型调用使用宿主端口 22888 的 /v1；调度管理使用 /scheduler/api/v1。Router 直接连接应用自带的三个 Ollama 后端，不依赖 Model Hub 发现；同时自动发现 Image Studio、V-Voice、V-Music、ML Server 和视频结构化服务的可用模型。V-Voice 就绪后主动接入，自动绑定已校准的执行器与模型映射；详见界面的“应用接入”。

V-Voice 就绪模型自动继承应用资源预算并进入模型目录，已配置上游预算也适用于该上游新增的模型。可在“应用接入”和 API 文档查看接入方式及可用接口。请求和响应格式保持一致。

ARM CPU 主节点的 Image Studio SD Turbo 会在权重就绪后自动注册已校准执行器。可在 Image Studio「生成 → 计算节点 → 主节点」运行 F16、最大 512×512、4 步的单张生图。到 V-Scheduler 任务详情可查实际节点。生成 API 请求格式不变。

0.0.109 移除了调度控制器的容器内存上限，解决控制器达到旧上限时反复重启的问题。在 VOS 应用商店升级即可生效。推理资源准入、模型预算和 API 契约沿用现有规则。

安装时会检查 PGV 依赖。首次打开应用并以 VOS 管理员登录后，自动创建专用数据库、普通数据库角色和本机资源采集身份；配置保存在应用专属 ${VOS_APP_STORAGE_PATH}/config 中。无需准备配置文件或执行终端命令。PGV 不可达时页面显示初始化状态。

首次配置中断后会继续未完成的步骤，正常重启复用已有数据库。已配置实例遇到数据库或账号异常时，页面会提示恢复数据库或修正连接配置。首次配置失败后，处理页面提示并点击「重试连接」。

管理界面支持按节点查看执行任务、等待顺序和近期结束任务，提供取消、受控重试和人工删除。连接前可查看明确标注的演示；样例操作不影响真实任务。界面默认跟随 VOS 语言，可选择简中、英文或繁中。

本机资源采集是本应用内置组件，安装后自动启动、初始化本机节点并保存内部身份，无需单独部署 Agent、运行终端命令或填写采集凭据。CPU 支持展开查看逐逻辑处理器占用；Jetson Thor 的 CPU/GPU 共用一份系统内存，不额外显示独立显存池。

安装位置与计算位置分别记录。V-Router 云端推理不预约本地资源，本地模型以实际执行节点申请许可。未确认停止的执行保留预约；只有已停止终态任务允许软删除，业务输出仍由原应用管理。

本版支持 VOS 管理员登录和自动本机采集；HA 与设备级多 GPU 分配尚未实现。

管理页提供最近 24 小时的排队等待、执行占用 P50/P95、任务失败率和模型许可历史。任务详情持续更新，支持状态时间线、每次执行的分配/停止时间、等待原因建议及受控重试。列表可按状态、应用、节点组合筛选，搜索业务任务 ID；默认最近 200 条，可加载更早任务。P95 至少需要 20 个有效样本，旧许可释放时间未知时保持未知。

节点管理显示 SSH 算力节点、登记预算、执行器和服务凭据。登录用户可以查看节点清单，配置操作需要管理员身份。

管理员可从 V-Scheduler 的左侧导航打开「推理部署」。部署列表、详情和模型卡片在当前工作区打开。存储集群由独立的 VOS 集群管理应用维护。已有部署可在「节点管理 → 迁移 ModelInfer 部署」导入。「API 文档 → 调度管理 API」提供既有迁移和运行时接口。

在「节点管理 → 节点与权限 → VOS 应用发现的节点」可查看与「资源与任务 → 执行资源」一致的宿主机实测数据，包括 CPU 使用率与逻辑处理器数、内存已用／总量／可用、GPU 使用率及采样时间。采样缺失或过期时会显示暂不可用。节点发现记录可以仍然有效。两处沿用调度管理 API 的 GET /nodes，内置推理采样位于 modelinfer_source.node.host_resources。

VOS 确认旧版 ModelInfer 未安装或已卸载后，内置推理运行时会自动启动。如需保留旧部署，请先停用旧应用并从「节点管理 → 迁移 ModelInfer 部署」导入。权重首次下载失败且未生成文件时，可以在「权重管理」删除该卡片。

推理部署在运行时启动或断线时保留全部页签，内容区显示原因并自动重试。也可点「重试连接」，无需刷新整个页面。调度管理 API 中的运行时健康检查沿用原有接口。

在「推理部署 → 推理镜像」可查看已公开的镜像地址和适用 Profile。管理员可登记镜像、勾选内置 Profile 或添加自定义名称。在「节点管理 → SSH 算力节点」编辑节点可指定这些名称。

## Host alias、内部端口与宿主机端口

以下是所有 profile 共用的默认映射。`<vos-host>` 为安装该应用的 VOS 宿主机 IP 或域名；192、229、232 三台测试机分别使用 `192.168.1.192`、`192.168.1.229`、`192.168.1.232`。内部地址仅在 Docker `vos_default` 网络解析，完整 URL 在地址前加 `http://`。安装时修改端口参数后，以实际安装值为准；应用内「API 文档 → 模型管理 API」显示配置后的地址。

统一容器的正式 host alias 只有 `v-scheduler`，通过 `8080`、`38120`、`6005` 区分网关、调度和模型管理；该容器其余名称全部保留为兼容别名。新应用和已有应用后续适配均推荐使用 `v-scheduler`。三个 Ollama 独立容器保留各自名称。

| 功能 | Docker host alias:内部端口（含全部兼容别名） | 宿主机 host:外部端口 | 主要路径与用途 |
|---|---|---|---|
| 统一推理、网关管理及统一界面 | `v-scheduler:8080`; 兼容：`v-scheduler-gateway:8080`、`v-router:8080`、`v-router-backend:8080` | `<vos-host>:22888` | `/v1/*` 推理；`/api/v1/*` 网关管理；`/` 界面 |
| 调度接管与资源管理 | `v-scheduler:38120`; 兼容：`v-scheduler-backend:38120`、`v-scheduler-frontend:38120` | `<vos-host>:38120` | `/api/v1/*` 任务、许可、节点、执行器及统计 |
| 模型仓库管理 | `v-scheduler:6005`; 兼容：`v-scheduler-model-hub:6005`、`v-scheduler-model-hub-backend:6005` | `<vos-host>:36005` | `/api/v1/*` 模型、选中文件下载、更新、导入、别名、引用和后端管理；`/openapi.json` |
| Ollama QA 原生管理 | `v-scheduler-ollama-qa:11434` | `<vos-host>:12434` | `/api/*` 模型清单、拉取、详情、加载/卸载及原生推理 |
| Ollama QA 推理网关 | `v-scheduler-ollama-qa:11535` | `<vos-host>:12535` | `/v1/chat/completions` 聊天；`/metrics` 指标 |
| Ollama Embedding 原生管理 | `v-scheduler-ollama-embedding:11434` | `<vos-host>:12435` | `/api/*` 原生模型管理及向量推理 |
| Ollama Embedding 推理网关 | `v-scheduler-ollama-embedding:11535` | `<vos-host>:12536` | `/v1/embeddings` 向量；`/metrics` 指标 |
| Ollama Rerank 原生管理 | `v-scheduler-ollama-rerank:11434` | `<vos-host>:12436` | `/api/*` 原生模型管理及重排推理 |
| Ollama Rerank 推理网关 | `v-scheduler-ollama-rerank:11535` | `<vos-host>:12537` | `/v1/rerank` 重排；`/metrics` 指标 |

可配置的外部端口参数：

- `V_ROUTER_HOST_PORT`：默认 `22888`。
- `SCHEDULER_HOST_PORT`：默认 `38120`。
- `MODEL_HUB_BACKEND_HOST_PORT`：默认 `36005`。
- `OLLAMA_QA_HOST_PORT`：默认 `12434`。
- `OLLAMA_QA_GATEWAY_HOST_PORT`：默认 `12535`。
- `OLLAMA_EMBEDDING_HOST_PORT`：默认 `12435`。
- `OLLAMA_EMBEDDING_GATEWAY_HOST_PORT`：默认 `12536`。
- `OLLAMA_RERANK_HOST_PORT`：默认 `12436`。
- `OLLAMA_RERANK_GATEWAY_HOST_PORT`：默认 `12537`。

同一行的兼容别名指向同一个容器和端口，不产生额外服务或宿主机映射。`host.docker.internal` 是网关容器中的 Docker 宿主机别名（`host-gateway`），用于访问宿主机已发布端口，例如 `host.docker.internal:38120`；它不是新增服务，也没有单独的固定端口。

网关还在同一 `22888` 端口提供 `/scheduler/api/v1/*` 调度代理和 `/model-hub/api/v1/*` 模型管理代理。VOS 内统一入口为 `/app/com.ictrek.v-scheduler/`；模型管理前缀为 `/app/com.ictrek.v-scheduler/model-hub/api/v1/*`，网关 API 前缀为 `/api/com.ictrek.v-scheduler`。三个 Ollama 的 `11535` 是各后端推理/指标入口；跨后端统一模型名和调度入口使用 `v-scheduler:8080/v1/*` 或 `<vos-host>:22888/v1/*`。

这些别名由 V-Scheduler 自己声明；原 Model Hub 的别名、端口及共享目录保持原应用所有权。共享模型目录仍在安装时选择，沿用原 Model Hub 所选公共目录即可。

开启驻留时，已验证身份调用内置 Ollama 且未指定排队头，默认有界等待 30 秒；显式排队头 0、匿名调用和其他后端保持立即准入或拒绝。

### 应用统一接入

节点管理新增「应用统一接入」，汇总应用心跳、节点状态、批准预算和停止请求。应用通过调度 API `/integrations` 登记已批准执行器，按响应间隔心跳；停止后必须以原执行身份确认原生退出和权重卸载才能释放预约。节点采集随 VOS App 自动运行，无需 SSH 或手工部署 Agent。旧应用自动绑定保持兼容，尚未实现新停止协议的应用不宣称已接管。详见应用内「API 文档 → 应用接入」及仓库统一接入指南。

在使用 Traefik v3 的 VOS 上，从浏览器直接打开应用根地址会跳转到 VOS 应用页面。嵌入页面和 API 请求沿用原有路由。

管理员可在「资源与任务 → 执行资源」查看仅观察节点的逻辑 CPU 数和利用率、内存已用／总量／可用、GPU 利用率与采样时间。共享内存只计一次。内置推理使用已保存的 SSH 连接采集，缺失或过期的数据会明确标出。数据也可通过管理员调度 API GET /nodes 读取。

### 应用后端部署

在「API 文档 → 调度管理 API → 应用后端部署」查看完整权限、字段和状态。已登记节点对所有已认证的 VOS 应用可见。应用按其已安装 Compose 中的发布镜像清单和节点固定 Profile 选择部署目标。应用提交镜像、节点和容器端口到 POST /backend-deployments；轮询状态为 running 后读取 endpoint。SSH 节点使用 Docker，受信 VOS 集群成员使用 VOS Projects。停止保留宿主机端口，删除并确认清理后释放。

管理员也可在「节点管理 → 应用后端」直接登记应用、选择目标和 Profile。部署表单保存镜像、容器端口、可选宿主机端口、CPU 和内存上限及后端 JSON 配置。选择「API 文档 → 调度管理 API → 应用后端部署」可查看 SSH 和集群两种完整示例。

在「权重管理 → 推理服务」中，管理员可为内置对话、向量和重排实例分别设置「自动预热」。开关默认沿用安装设置，修改后会保留。开启时按调度预算预热配置的模型标签，缺少权重时先下载。关闭后不再开始新的预热，当前请求自然结束。预热完成后仍按模型空闲保留策略卸载。需要排查时看卡片的预热状态。

GET /api/v1/ollama-preload · PUT /api/v1/ollama-preload

推理应用登记的模型可由 VOS 管理员在「模型与上游 → 模型访问 Key」生成、设置或撤销专用 Key。该 Key 归签发管理员管理，仍只授权所选私有模型。公共模型可直接调用。

在「节点管理 → SSH 算力节点」添加或编辑节点时，可关闭应用后端的 Model Hub NFS，让该节点直接复制权重。已有后端停止后重新启动以更新挂载。原来使用共享权重的模型需重新准备。

删除单个 Image Studio 远端模型时，使用 `DELETE /backend-deployments/{id}/models/{model_id}`。该操作要求部署所属应用或管理员身份及支持删除的 Worker。存在活跃任务时返回 `BACKEND_TASKS_ACTIVE`。清理失败后可重试同一请求，期间该模型停止新任务准入。成功回执的 `data.deleted_transfers` 为本次移除的目标传输记录数。
